给Hexo博客文章/页面加密

发表于 2026-11-21|更新于2026-11-21|Hexo教程
|字数总计:4331|阅读时长:14分钟|阅读量:—

这篇文章是公开的，故意不加密码——否则你还没学会怎么解锁，就先被拦在门外了。

本文按“我从来没用过 Hexo 加密插件”的起点来写。你看完应该能独立完成三件事：

  1. 给某一篇文章加密码；
  2. 给某个页面加密码；
  3. 让加密内容不要出现在 RSS、站内搜索、Google / 百度 sitemap 里。

不需要另外下载任何文件。核心加密只需要一条 npm install hexo-blog-encrypt --save；插件会在生成时自动把 /lib/hbe.js 和 /css/hbe.style.css 放进 public/。第 10 节的解锁按钮、错误弹窗等属于可选增强，不抄也能正常加密和解锁。

后面还会讲本站实际做的那些“额外增强”：解锁按钮、错误弹窗、pjax 兼容、解密后目录和表格修复、隐藏“重新上锁”按钮等。

先说清楚安全边界：静态博客的“加密”是浏览器端解密。密文和解密脚本都会发到访客浏览器里，所以它适合“挡住随手点开的人”，不适合保护真正敏感的机密。真正重要的附件请放服务端鉴权后面。

阅读路线

如果你赶时间，可以按这个顺序跳：

你想做什么 看哪一节
我完全没装过插件 第 1、2 节
只想锁一篇文章 第 3 节
想锁一个页面，比如 /hours/ 第 4 节
想给一类文章统一密码 第 5 节
不想让搜索引擎收录 第 6 节
改完密码却提示错误 第 7 节
本地预览打不开 / 解锁后布局乱 第 8、9 节
想知道本站做了哪些增强 第 10 节
没有插件怎么办 第 11 节
上线前检查 第 12 节

第 0 步：先搞懂“加密到底发生在哪”

Hexo 是静态站生成器。你写的是 Markdown，Hexo 生成的是一堆 .html。

加密插件做的是：

  1. 在生成阶段，把文章正文用密码加密成一串密文；
  2. 把原文替换成一个锁屏界面；
  3. 在页面里放一段浏览器脚本；
  4. 访客输入密码后，浏览器在本地解密并显示正文。

记住这条分界线：作者本机负责加密，访客浏览器负责解密。站点服务器只保存密文和解密脚本。

所以有三个很重要的事实：

  • 密码正确与否，是在访客浏览器里判断的；
  • 解密用的密钥来自密码，不会明文写在生成后的 HTML 里；
  • 但如果有人把密文下载下来，理论上可以离线暴力猜密码。

本站当前使用的是 hexo-blog-encrypt 3.1.6。它构建期用 Node 自带 crypto，浏览器期用原生 WebCrypto（PBKDF2 + AES-CBC + HMAC），不依赖 crypto-js、jsencrypt 或外部 CDN。

第 9 步：解锁后目录、表格、滚动乱掉怎么办

这是 pjax 主题特别容易遇到的问题。

加密文章的正文不是页面加载时就存在的，而是访客输入密码后才插入 DOM。主题的目录生成、表格包装、滚动监听通常在页面加载时就跑完了，等正文出现时，它们已经“错过”了。

本站的表现曾经是：

  • 目录空白；
  • 表格没有圆角边框；
  • 目录高亮不跟随滚动；
  • pjax 进入文章后插件脚本没重新执行。

本站的解决方式在 source/js/unlock-secret.js：

  1. 监听 DOMContentLoaded；
  2. 监听 pjax:complete；
  3. 用 MutationObserver 盯着锁屏节点；
  4. 发现 /lib/hbe.js 没加载就补加载；
  5. 解密成功后调用主题暴露的同步函数。

10.5 pjax 兜底

主题开启 pjax 后，页面局部替换可能导致插件脚本没重新执行。本站做了三层兜底：

  1. pjax:complete 时重新初始化解锁脚本；

  3. 发现 /lib/hbe.js 不在 DOM 里就补加载一次。

本站插件注入的脚本本身带 data-pjax，主题 pjax 配置也会重新执行带这个属性的脚本。

第 11 步：没有加密插件时怎么办

这一步专门回答“我还没装插件，能不能学会 / 能不能先凑合”。

11.1 只写 password 没用

如果没装 hexo-blog-encrypt，front-matter 里写：

Hexo 只会把它当普通字段存着，不会加密任何内容。生成后的 HTML 里正文还是明文。

所以第一步永远是装插件，或者换别的真正做加密的方案。

11.2 纯前端“遮罩”不是加密

下面这种做法只能叫“藏一下”：

因为正文已经在 HTML 里了。访客按 F12 就能看到。

不要用 CSS 模糊、display:none、简单 JS 判断密码来做“加密”。那只是把钥匙挂在门上。

11.3 正确路线只有三条

路线 适合谁 说明
安装 hexo-blog-encrypt 绝大多数 Hexo 博主 本文主线，10 分钟能搞定
服务端鉴权 真机密、客户资料、付费内容 用 Nginx / Cloudflare Access / 自建登录
不放到公开站 极敏感资料 存网盘或内网，只放说明

11.4 如果暂时不能装插件

你可以先做这些低风险准备：

  1. 把要保护的内容从公开 source/ 里挪走；
  2. 在 robots.txt 里排除相关目录；
  3. 确认 PDF / NC 附件不在公开路径；
  4. 等能装插件时再按第 1～7 步补上。

但不要自欺欺人地认为“前端遮住了就安全”。

第 12 步：上线前检查清单

每次发布加密内容前，按这个表过一遍：

  • [ ] 已安装 hexo-blog-encrypt；
  • [ ] _config.yml 的 encrypt 段配置正确；
  • [ ] 文章或页面 front-matter 写了 password；
  • [ ] 同时写了 secret/indexing/sitemap/baidusitemap: false；
  • [ ] 密码里有特殊字符时已加引号；
  • [ ] 没有把真实密码写进公开文章或注释；
  • [ ] 执行了 hexo clean && hexo generate；
  • [ ] 日志里看到 hexo-blog-encrypt: encrypting ...；
  • [ ] 生成后的 HTML 里有 hbePass；
  • [ ] 用 localhost 或 HTTPS 打开测试；
  • [ ] 输错密码提示正确；
  • [ ] 输对密码正文正常显示；
  • [ ] 目录、表格、滚动高亮正常；
  • [ ] public/atom.xml 里没有该文章标题；
  • [ ] public/search.xml、sitemap.xml、baidusitemap.xml 里没有该文章；
  • [ ] 附件直链不能直接打开；
  • [ ] 修改过 inject 资源后 ?v= 版本号已更新。

常见问题对照表

现象 最可能原因 怎么查
页面完全没锁 没装插件 / 没写 password 看生成日志有没有 encrypting
提示密码错误 旧密文配新密码 hexo clean && hexo generate
提示“密码正确但内容可能已更新” HMAC 对不上 重新生成，确认没有手改 public/
本地解锁失败 不是 HTTPS / localhost 换 http://localhost:4444
pjax 进入后没锁屏 插件脚本没重跑 检查 data-pjax 和主题 pjax 配置
解锁后目录空白 目录生成早于正文插入 补一次目录同步
表格没样式 表格包装早于正文插入 补一次表格包装
搜索还能搜到标题 没写 indexing: false 检查 front-matter 和 search.xml
RSS 泄露 没写 secret: true 检查 atom.xml 和模板
改了没生效 缓存 升 ?v=、强刷、重启 server
访客无法重新上锁 本站隐藏了 Encrypt again 清 localStorage

最后再强调一次

  1. password 才是加密开关，其他四个字段只是防止泄露；
  2. 改密码后必须 hexo clean && hexo generate；
  3. 静态站加密不是高安全，别拿它保护真正敏感的东西；
  4. 附件不会被自动加密；

照着上面走一遍，你就已经超过大多数“只会复制 front-matter”的新手了。剩下的，就是把密码换成你自己的，然后亲手生成、解锁、排错。多看一遍日志，比背十条命令都有用。
