不用音乐插件，也能做出本站同款左下角音乐胶囊

发表于 2026-11-21|更新于2026-11-21|Hexo教程
|字数总计:5888|阅读时长:25分钟|阅读量:—

本站左下角那枚竖着的音乐胶囊，看起来像插件做的，实际上没有用 APlayer、MetingJS，也没有用任何“音乐插件”。它就是一个原生 <audio> 标签、一份歌曲数组、一个固定在左下角的 div，再加一点 CSS。

这篇教程按“我连音乐插件是什么都不知道”的起点写。你不需要装任何 npm 包，跟着做就能得到一个能播放、能显示歌词、能切歌、鼠标悬停会展开按钮的音乐胶囊。

核心思路只有一句话：全站只保留一个 <audio>，胶囊只是它的一个“遥控器 + 显示屏”。

文章第 2～4 节已经把三个文件的完整代码摆出来了，喜欢复制的话直接复制即可。下载链接放在文章最后。

第 0 步：先搞清楚“音乐插件”和“音乐胶囊”不是一回事

很多教程会让你装：

  • APlayer
  • MetingJS
  • hexo-tag-aplayer
  • 某个音乐解析插件

它们能快速生成一个播放器，但有几个问题：

  1. 样式是插件的，想改成“竖排胶囊”要覆盖一堆你不懂的选择器；
  2. 插件通常自己创建一个 <audio>，你再加一个胶囊，就会出现两个播放器各放各的；
  3. pjax 换页后，插件实例可能被销毁；
  4. 移动端、歌词、自动播放限制都得围着插件的规则转。

本站的做法是把这些全拆开：

角色 谁负责
真正发声 一个原生 <audio>
歌曲队列 / 播放状态 自己写的 music-bus.js
左下角胶囊 UI 自己写的 music-capsule.js
外观 自己写的 music-capsule.css
第三方音乐接口 可选，服务端代理；新手阶段完全不需要

中间的 music-bus.js 是唯一播放核心；左下角胶囊、侧栏面板和 /music/ 页面都只是它的“遥控器 + 显示屏”。

所以这篇教程不装插件。你只需要会复制三个文件、改一处配置。

现代浏览器不允许网页自动播放带声音的媒体。所以：

  • 页面刚打开就自己响：不行；
  • 访客点了一下播放键：可以。

如果你在控制台看到 play() failed because the user didn't interact with the document first，不是代码错了，是浏览器在保护用户。

不要用“静音自动播放再取消静音”去绕过限制，很多浏览器已经堵了这条路。老老实实让用户点一次播放键。

第 7 步：为什么这套方案不需要音乐插件

插件做的事情，其实就是帮你生成：

这些东西原生 HTML 都有。我们只是把它们组织得更有条理：

插件方案 本教程方案
插件创建 <audio> 自己 document.createElement('audio')
插件管理队列 自己一个 queue 数组

插件给样式 自己写 CSS
插件处理 pjax 自己监听 pjax:complete

所以你并没有“少用什么能力”，只是把能力拆开自己拿回来了。

第 9 步：翻页音乐不断——pjax 与整页刷新

9.1 pjax 跳页

pjax 只替换页面的一部分，不会销毁整个 <audio>。所以本站的胶囊能在站内跳页时继续播放。

你要保证两件事：

  1. 播放核心脚本不要放在会被 pjax 替换的正文容器里；
  2. 胶囊脚本监听 pjax:complete 补建 DOM。

第 10 步：手机端与常见限制

10.1 手机端没有 hover

桌面端靠 :hover 展开按钮，手机端没有真正的悬停。本站最后保留了“常驻胶囊”，没有改成“点一下才展开”，因为多点一次才能切歌更麻烦。

教程版 CSS 里手机端只是把胶囊缩到 48px，没有隐藏按钮区域。如果你愿意，也可以点播放键时临时加一个 .is-open 类展开。

10.2 音频和封面都要 HTTPS

站点是 HTTPS 时，下面这些都会失败：

浏览器会报混合内容错误。全部换成 HTTPS。

10.3 跨域不是“音频播放”的主要障碍

普通 <audio src="https://..."> 直接播放通常不需要 CORS；但如果你要：

  • 读歌词；
  • 读封面画布；
  • 做频谱；
  • fetch JSON 歌单；

那就需要对方给 CORS 头，或者走同源代理。本站的频谱方案最后没用，就是因为 CDN 不给 Access-Control-Allow-Origin。

10.4 overscroll-behavior: contain 别乱加

在歌词列表上加这个属性，会阻止滚动传给父级，看起来像“页面卡住”。本站踩过这个坑，后来删掉了。

现象 最可能原因 怎么查

手机端挡正文 胶囊太宽 / 高度写死 检查 @media (max-width:600px)

第 12 步：上线前检查清单

  • [ ] 三个文件都在 source/ 对应目录；
  • [ ] CSS 在 inject.head；
  • [ ] JS 在 inject.bottom；
  • [ ] music-bus.js 排在 music-capsule.js 前面；
  • [ ] 音频地址是 HTTPS；
  • [ ] 歌单里至少有一首能直链的 mp3；
  • [ ] 第一次播放由点击触发；
  • [ ] 桌面端悬停能展开按钮；
  • [ ] 手机端胶囊不挡正文；
  • [ ] 深色模式下文字看得清；
  • [ ] pjax 翻页后胶囊还在；
  • [ ] 改过文件后 ?v= 版本号已更新；
  • [ ] hexo clean && hexo generate 通过；
  • [ ] 没有把任何 Cookie、token、私有 API、服务器路径写进公开页面。

最后说一句

音乐胶囊最难的地方不是“让声音响起来”，而是让全站只有一套状态：一首歌、一个进度、一个播放意图，所有界面都只是它的镜子。

你先把教程版的 52px 胶囊跑起来，再慢慢加面板、歌单、歌词、续播。不要一开始就把 QQ 音乐接口、pjax、BroadcastChannel 全堆上——那是本站踩了二十多次坑之后的形状，不是第一步该长的样子。
